# Threat model

BlockMine is a self-hosted Minecraft bot framework. One install is one operator's panel: an Express API and a Vite SPA on port 3001, SQLite in `~/.blockmine/blockmine.db`, and one child process per bot. Bots speak Minecraft through Mineflayer. Behavior comes from JavaScript plugins and from visual graphs. The panel also exposes Socket.IO and an MCP endpoint at `POST /api/mcp`.

The operator chooses the host, the Minecraft accounts, and the servers. Other panel users, other players on those servers, and the Minecraft server itself are not the operator.

## What this project does and where untrusted input enters

Panel HTTP is plain HTTP. A fresh install has no users. `GET /api/auth/status` and the setup route are public until the first panel user exists. After that, setup must stay closed. Login and password recovery are public and rate-limited. Everything else under `/api` needs a Bearer JWT or a panel API key that starts with `pk_`.

Permissions are the string ids in `backend/src/api/routes/auth.js` (`bot:*`, `management:*`, `plugin:*`, `server:*`, `proxy:*`, `task:*`, `panel:*`, `graph:*`). `authorize` treats `*` as every permission. The panel user with the lowest id is the owner and is the only account that may change roles. A Viewer role is read-only. `checkBotAccess` must restrict a user to the bots they were granted.

Four more inputs are untrusted even after login:

- Plugin files and plugin `package.json`. `plugin:develop` (the in-panel IDE) and `plugin:install` (GitHub, zip, or a local path) load JavaScript with `require` / `import` inside the bot process. That is the product. Those two permissions are host code execution for a bot the user can access. `plugin:settings:edit` changes that plugin's settings. It is not a license to write arbitrary files.
- Visual graphs and debugger expressions. Users with `management:edit` edit and run graphs for bots they can access. Breakpoint conditions go through `backend/src/core/utils/safeExpression.js`, a small expression language. They must not become JavaScript, `Function`, or `eval`, and they must not see `process`, `require`, or the filesystem.
- Minecraft chat, commands, and packets. Players and the server are untrusted. A command runs only when the bot's own permission, chat-type, and cooldown checks allow it. Owner bypass applies to usernames configured as that bot's owners.
- API keys. A `pk_` key acts as the panel user who created it and must not gain permissions that user does not have. Bot API keys on the bot-API socket are a separate credential. A read-only bot key must not perform writes, and the username in a socket payload must not be treated as proof of an in-game identity.

SQLite stores bcrypt password hashes, Minecraft account passwords, proxy passwords, and API-key hashes. The JWT secret and the bind address live in `~/.blockmine/config.json`. Those values must not come back in API responses, MCP tool results, logs shown to a lesser user, or the SPA.

## Components that matter most / least

Matter most:

- `backend/src/api/middleware` and every route that mounts `authenticate`, `authenticateUniversal`, `authorize`, or `checkBotAccess`. A route that changes a bot, a plugin, a user, or a file and skips one of these is in scope.
- `backend/src/api/routes/pluginIde.js`, plugin install and import/export in `bots.js`, and `backend/src/core/PluginManager.js`. Path checks have to stay inside that bot's plugin directory. An install path that becomes the filesystem root is critical.
- `backend/src/api/mcp`, including permission checks on each tool.
- `backend/src/real-time`: the root Socket.IO namespace, the panel namespace, and the bot-API namespace.
- `backend/src/core/PluginLoader.js` and `backend/src/core/utils/npmInstall.js`.
- Graph execution (`GraphExecutionEngine.js`) and `safeExpression.js`.
- In-game command handling (`BotProcess.js`, command permission checks).

Matter less, and only when they cross one of the boundaries above:

- React pages, i18n JSON, the 3D viewer, and Monaco as an editor.
- `node_modules`, Mineflayer, and Prismarine. A bug that exists only inside those libraries is out of scope. It is in scope when BlockMine feeds untrusted chat, a URL, a path, or a graph into them in a way that escapes the bot.
- `services/`, the stats server, the landing site, and `packages/blockmine-mcp`. They are not this process. The MCP server that matters is `POST /api/mcp` inside the panel.

## How to exercise it

The Dockerfile installs dependencies and builds the SPA the way a host install does: `npm install`, then `npm run build`. Prisma Client is generated by `scripts/postinstall.js`. Node 22. No Minecraft server is required.

Jest covers repositories, services, and a lot of the API with Prisma mocked:

```
npm test --workspace=backend
```

Tests live in `backend/src/**/__tests__` and `backend/src/**/*.test.js`. `backend/src/__tests__/setup.js` sets `NODE_ENV=test` and mocks `backend/src/lib/prisma.js`. A failing assertion there is a regression. There is no browser end-to-end suite.

To boot the panel inside the image:

```
node backend/cli.js
```

That creates `~/.blockmine`, runs `prisma migrate deploy`, and listens on the host and port from config (port 3001). The first process start is the unauthenticated setup window. After one user exists, call the API with `Authorization: Bearer <jwt>`. Socket.IO expects the JWT in `handshake.auth.token`. MCP is `POST /api/mcp` with the same header.

The image has no network after the build. Do not add a test that clones GitHub, calls the npm registry, or joins a public Minecraft server.

## How you rate severity

Critical:

- Code execution, arbitrary file read, or arbitrary file write without `plugin:develop` or `plugin:install`, including before login.
- Authentication bypass that yields the owner, `*`, or any plugin-write permission.
- A `pk_` or bot API key that ends up with more rights than the account that created it.
- Reading or changing `~/.blockmine` (JWT secret, bot passwords, proxy passwords, raw API keys) from a user who was not granted that bot.
- SQL that reads or writes the panel database past the caller's permission.

High:

- A signed-in user reaches another user's bot or a permission they were not given. Cross-bot IDOR is high, not informational.
- Stored XSS that runs in another panel user's browser.
- A request from `management:edit` (without plugin install or plugin develop) to link-local, loopback, or private addresses, including cloud metadata.
- A Minecraft player or the Minecraft server reaching the panel host, writing a file, or running a command the bot's permission check would refuse.
- An expression or graph value that escapes `safeExpression.js` into JavaScript.

Medium:

- Reflected XSS.
- Unauthenticated denial of service that is cheap to trigger, including login and key-check amplification.
- A graph with no step or time limit. A user who can already edit graphs can stall the process. Cap this at medium.
- An error response that leaks a path or a SQL fragment and does not leak a secret.

Low:

- Missing headers on top of the ones already set in `server.js`.
- Denial of service that needs `plugin:develop`, `plugin:install`, or the owner.
- Self-XSS.

Not a vulnerability:

- The panel speaks HTTP and may bind `0.0.0.0`. That is how a VPS install is documented. Do not report the lack of TLS or the bind address by itself.
- A user who already has `plugin:develop` or `plugin:install` on a bot they can access can run JavaScript in that bot process, and a plugin `package.json` can run install scripts. Do not report the missing sandbox.
- The operator can read their own SQLite file on disk.
- A dependency advisory whose vulnerable function is not reachable from the inputs above.
- Copy, locale files, and layout.

When a patch is possible, prefer the middleware that already exists (`authenticateUniversal`, `authorize`, `checkBotAccess`) over a new auth mechanism. Keep the permission ids. A fix that deletes plugin loading, or that needs a live Minecraft server, is not useful.

## Anything to leave alone

- Do not spend time on `frontend/src` except where it stores the JWT, builds an API or socket call, or renders plugin-controlled HTML.
- Do not audit `node_modules` as if it were our source.
- Do not require a public proof of a memory-safety bug. This is JavaScript. A concrete request, socket event, or chat line is the reproducer.
- In-game owners bypass command cooldown and permission on purpose. Report a hardcoded owner the operator cannot turn off. Do not report the bypass itself when the username is configured on that bot.
- `GET /api/auth/status` being public is intended.
